需要设计一款浏览器插件。

主要功能：集成浏览器自动化的能力，让用户可以通过插件在现有的一个 toB 系统中，进行自动化操作。

插件需要支持以下功能：
1. 有图形界面，能够接收提示词，比如：“我想删掉昨天的车辆数据”，然后根据提示词，进行自动化操作。
2. 能够和一个 Agent 通信，Agent 能够理解提示词并转换成对应的自动化操作。

技术方案：
1. 浏览器插件使用 vite 搭建，使用 React 和 Tailwind CSS 进行开发。
2. 自动化能力基于 playwright-crx。
3. Agent 使用 langchain 和 openai 实现。
4. “现有的 toB 系统”，就是一个单纯的“某某车辆实时管理系统”，里面就是普通的简单的增删改查。
5. 插件使用 http 接口和 Agent 通信。
6. 暂时可以不考虑RAG的能力。

现有资产：
1. 本地的环境变量里，有火山引擎的的API Key，可以用来调用火山引擎的API。变量名字是：VOLCENGINE_API_KEY。
2. 本地有python开发需要的 miniconda 和 uv 环境。
3. 本地有 node 需要的 nvm 环境。
4. 本地有 chrome 浏览器。
5. 我开通的火山引擎的模型是“Doubao-Seed-2.0-lite”，Langchain 代码中需要查找模型对应的模型ID。

基本业务流程：
1. 用户在插件的图形界面中，输入提示词，比如：“我想删掉昨天的车辆数据”。
2. 插件将提示词发送给 Agent，Agent 理解提示词，并转换成对应的自动化操作。
3. Agent 给插件返回了一组 playwright-crx 的自动化操作。
4. 插件执行 playwright-crx 的自动化操作。
5. 自动化操作完成后，插件将结果返回给用户。

项目应该包含三个部分：
1. 一个简陋的老旧的 toB 系统，里面就是普通的简单的增删改查。
2. 一个 Chrome 插件。
3. 一个 Agent。

三个部分应该分别放在三个不同的目录下。

验收：
1. 插件能够正常安装和运行，能够接收提示词，并根据提示词，进行自动化操作。
2. Agent 能够理解提示词并转换成对应的自动化操作。
3. 插件和 Agent 能够正常通信。
4. 老旧的 toB 系统足够简单，甚至不需要做真正的数据库和API接口，身份认证都可以不做。
